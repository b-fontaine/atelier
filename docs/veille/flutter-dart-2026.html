Flutter et Dart en 2026

Ce qui a changé cette année, ce qui casse, et ce qu'un développeur Dart/Flutter doit surveiller. État au 21 novembre 2026.

L'essentiel

  • Flutter 3.50 est la version stable depuis le 11 novembre, avec Dart 3.14. Un correctif 3.50.1 est sorti le 20 novembre : installez 3.50.1, jamais 3.50.0.
  • Material et Cupertino quittent le SDK. material.dart et cupertino.dart sont dépréciés, remplacés par les paquets material_ui et cupertino_ui. C'est le changement de l'année.
  • La chaîne d'outils bouge partout à la fois : SwiftPM sur iOS, Kotlin intégré et AGP 9 sur Android, nouvelles versions des outils de génération de code.
  • Le langage Dart a peu évolué : deux ajouts réels dans l'année, et deux versions sur quatre sans aucune nouveauté de langage.
  • Les générateurs de code ne sont plus tous compatibles entre eux. C'est le risque le plus concret pour un projet existant.

D'où viennent ces informations

Cette page reprend un rapport de veille fondé surtout sur les billets, docs et changelogs officiels de Flutter et Dart. Quelques points n'ont pas pu y être vérifiés ; ils sont signalés par non vérifié. Les points portant testé ici ont été contrôlés dans ce dépôt le 21 novembre 2026.

1. L'année en une frise

Quatre versions stables de Flutter et quatre de Dart, sorties ensemble. La cadence trimestrielle, avec des dates de coupe publiées à l'avance, est une nouveauté de 2026 et elle a été tenue.

2. Les points de vigilance

Si vous ne retenez qu'une section, c'est celle-ci. Elle est classée par urgence.

À traiter avant le 2 décembre 2026 : le dépôt central CocoaPods passe en lecture seule. Si votre projet iOS a désactivé SwiftPM, réactivez-le maintenant.
  • Version de Flutter : passez directement en 3.50.1. La 3.50.0 exclut en silence les fichiers .env des paquets Android et casse les builds à types personnalisés.
  • Générateurs de code : figez les versions de build_runner, analyzer, freezed, json_serializable, injectable_generator et versionnez pubspec.lock. Voir la section 4.
  • Intégration continue : si elle refuse les avertissements (--fatal-infos), la dépréciation de material.dart la fera échouer sur des centaines de lignes. Un projet open source en a compté 237 le lendemain de la sortie.
  • Migration Material : faites-la dans une demande de fusion isolée, jamais mélangée à la montée de SDK.
  • Rendus de référence (goldens) : régénérez-les à chaque montée de version. Plusieurs changements de rendu sont passés cette année.
  • iOS : vérifiez vos AppDelegate personnalisés pour UIScene, obligatoire avec le SDK iOS 27 ; minimum iOS 15.
  • Mac Intel : ils ne sont plus testés. Planifiez le remplacement de ceux de votre CI.
  • Android : vos plugins internes doivent passer au Kotlin intégré, sinon ils ne se construiront plus sous AGP 10.
  • Web : dart:html, dart:js et package:js sont dépréciés. Ajoutez --no-deprecated-js-interop à votre build pour débusquer les dépendances qui les utilisent encore.
  • Dart 3.13 : final et var ne sont plus acceptés sur certains paramètres. dart migrate corrige automatiquement.

L'ordre conseillé pour monter de version

  1. Le SDK seul, de 3.47 à 3.50.1.
  2. dart migrate --dry-run, puis dart migrate --apply --step=prepare, avant de relever la contrainte de SDK.
  3. dart fix --apply --code=migrate_design_widgets pour passer à material_ui.
  4. La régénération des rendus de référence.

Quatre demandes de fusion distinctes : si une régression apparaît, vous saurez laquelle l'a introduite.

3. Material quitte le SDK

Jusqu'ici, les widgets Material et Cupertino faisaient partie de Flutter lui-même. Ils deviennent deux paquets ordinaires, publiés chaque semaine, indépendamment du SDK.

VersionÉtape
3.44 (mai)Gel : plus d'évolution de Material et Cupertino dans le cœur.
3.47 (août)material_ui et cupertino_ui sortent en 1.0 ; adoption facultative.
3.50 (novembre)package:flutter/material.dart et cupertino.dart sont dépréciés ; flutter create utilise material_ui.

Ce que vous y gagnez

Les évolutions de design (Material 3 Expressive, Liquid Glass) arrivent sans attendre une version de Flutter.

Ce que cela coûte

Une migration à faire, des montées de version majeures en cascade dans vos dépendances d'interface, et un paquet qui peut casser chaque semaine : figez sa version.

Ce qu'on ne sait pas

Aucune date de suppression des anciens imports n'est annoncée. Vous avez du temps, mais pas de calendrier.

Comment migrer

dart fix --apply --code=migrate_design_widgets
  • Si l'outil échoue sur pubspec.yaml (bogue connu) : lancez flutter pub add material_ui, puis relancez la commande.
  • MaterialUiCompatibilityBridge permet de migrer votre application alors que certaines dépendances utilisent encore les anciens imports.
  • Un seul délégué de localisation suffit désormais : GlobalMaterialLocalizations.delegates couvre aussi Cupertino et Widgets.

4. Le conflit des générateurs de code

Les macros de Dart ont été abandonnées en janvier 2025 et rien ne les remplace : build_runner reste la seule voie pour générer du code. Or ses dernières versions exigent le paquet build en version 5, que tous les générateurs ne suivent pas encore.

Constat : injectable_generator plafonne à build 4. Il ne peut pas être installé avec build_runner 2.17.x, ni avec bdd_widget_test 3.1.0 qui exige build 5 testé ici.
Une combinaison s'installe testé ici : analyzer 14.1.0, build 4.0.11, build_runner 2.16.1, injectable_generator 3.1.3, bdd_widget_test 3.0.5, freezed 4.0.3, json_serializable 6.15.2. Le test ne porte que sur l'installation des dépendances : la génération elle-même n'a pas été exécutée.

Le rapport d'origine affirmait qu'on ne pouvait plus avoir freezed et injectable à jour ensemble. Le test montre que freezed n'est pas en cause : le blocage vient uniquement du passage à build 5.

5. Flutter 3.50 dans le détail

Appeler le natif directement

FFIgen (Objective-C) et JNIgen (Java, Kotlin) deviennent stables. On appelle les API natives sans passer par un MethodChannel, y compris de façon synchrone et depuis un isolate d'arrière-plan.

C'est la vraie nouveauté technique. Vos plugins existants continuent de fonctionner. Gardez une interface devant le code généré : il est verbeux et difficile à simuler en test.

Latence tactile sur iOS

Les événements sont transmis immédiatement au framework : une image de moins de latence, soit 16 ms à 60 Hz et 8 ms à 120 Hz.

Sécurité Android

En version publiée, les paramètres de route et de point d'entrée venant d'une autre application sont ignorés, et les drapeaux moteur rejetés. Si vous utilisez des liens profonds par ce biais, vérifiez-les.

Nouveautés du framework

Découpe de zones défilantes, hauteur d'élément par constructeur dans les listes séparées, saisie de code à usage unique reçu par courriel, réduction des animations, fermeture des infobulles par Échap.

Ce que le correctif 3.50.1 répare

Problème de la 3.50.0Qui est touché
Fichiers commençant par un point (.env) et dossiers préfixés _ exclus en silence des paquets AndroidToute application qui embarque sa configuration en asset
Builds Android cassés avec des types de build personnalisés dès qu'un plugin est présentLes projets à variantes (recette, préproduction…)
Affichage décalé sous Linux avec certains pilotes, Nvidia comprisLes applications desktop Linux
index.html supprimé après deux builds web successifs avec puis sans hachage de contenuLes déploiements web
Texte figé en mode WebAssembly sous isolation cross-originLes applications web en Wasm multi-fil

Deux régressions desktop restaient signalées à la mi-novembre : un plantage sous Windows au redimensionnement quand Impeller est désactivé, et des dégradés mal rendus avec OpenGL ES.

Ruptures de comportement à connaître

  • Les césures conditionnelles affichent maintenant un trait d'union.
  • L'ordre des widgets insérés dans un texte de droite à gauche change.
  • ignoringSemantics est supprimé de IgnorePointer et AbsorbPointer.
  • SafeArea se comporte différemment sur le web avec viewport-fit=cover.

6. Plateforme par plateforme

Web

  • WebAssembly : actif par défaut sur Chrome et Edge 137+ ; à activer soi-même pour Safari 26.2+ et Firefox 147+.
  • Nouveau drapeau --web-content-hash pour gérer proprement les caches.
  • Les anciennes bibliothèques d'interop JavaScript sont dépréciées.
  • Le gain « deux fois plus d'images par seconde » en Wasm vient d'un banc d'essai interne de Google, non reproduit.

Desktop

  • Impeller est le moteur de rendu par défaut sur macOS, Windows et Linux depuis 3.47.
  • Canonical pilote désormais le desktop à la place de Google.
  • Le multi-fenêtres reste expérimental : ses API ont encore été renommées en 3.50. Ne le planifiez pas en production.

iOS et macOS

  • SwiftPM est le gestionnaire par défaut depuis 3.44 ; CocoaPods se fige le 2 décembre.
  • Minimum iOS 15 et macOS 12 depuis 3.47.
  • UIScene obligatoire avec le SDK iOS 27.
  • Les Mac Intel ne sont plus testés ; une future version exigera Apple Silicon, y compris pour construire Android.

Android

  • Nouveaux projets : AGP 9.3.1, Gradle 9.5.0, Java 17 minimum, SDK cible 36, SDK minimum 24.
  • Kotlin est intégré à AGP : les plugins qui l'appliquent encore à la main cesseront de fonctionner sous AGP 10.
  • Le nouveau mode de composition des vues natives (HCPP) reste à activer soi-même en stable.

L'effort de l'année a porté sur les outils, le web et l'interop bien plus que sur le langage.

Ce que les deux ajouts apportent

Les primary constructors et les paramètres nommés privés réduisent le code répétitif des classes de données. Entités, cas d'usage et états peuvent souvent s'écrire sans générateur.

Ce qui n'arrivera pas

Les macros sont abandonnées depuis janvier 2025. Les augmentations n'ont rien livré de stable cette année. La génération de code reste donc là pour longtemps.

Ce qui se prépare

Dart 3.15, encore en préparation, prévoit des améliorations de la promotion de type et les extensions statiques. Rien n'est sorti.

8. Tests et rendus de référence

Aucune rupture directe dans flutter_test ni integration_test cette année. En revanche, les rendus de référence sont exposés à plusieurs changements :

  • le trait d'union visible sur les césures et l'ordre des widgets en texte de droite à gauche (3.50) ;
  • Impeller par défaut sur desktop, qui modifie l'anticrénelage sous Windows et Linux (3.47) ;
  • la bibliothèque de couleurs de Material, qui peut décaler les teintes générées à partir d'une couleur de base (3.41).

Régénérez-les à chaque montée de version et faites-les tourner dans une tâche d'intégration continue séparée.

Côté BDD, bdd_widget_test utilise depuis sa version 3 l'analyseur Gherkin officiel : un fichier .feature mal formé, toléré auparavant, fait maintenant échouer le build. golden_toolkit est abandonné ; une étape de comparaison de rendu est intégrée au paquet.

10. Écosystème et gouvernance

  • Canonical est responsable du desktop depuis mai.
  • Des RFC publiques existent maintenant pour Flutter comme pour Dart.
  • Plus de 70 % des demandes de fusion ouvertes viennent de contributeurs extérieurs à Google, selon une enquête du deuxième trimestre rapportée par une source secondaire.
  • Lecture possible : c'est un gage de pérennité, et aussi le signe que Google ne finance plus seul tous les fronts.
  • Le fork Flock, lancé fin 2024 par des contributeurs mécontents du rythme de Google, reste un symbole. Son activité réelle en 2026 n'a pas pu être établie non vérifié.

Chiffres avancés par Google, à prendre comme des déclarations : 1,5 million de développeurs par mois (en hausse de 50 % sur un an), 1,3 milliard de téléchargements mensuels sur pub.dev, plus d'un million d'applications sur Google Play. Flutter équipe aussi le système multimédia du Toyota RAV4 2026.
